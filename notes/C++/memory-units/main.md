# 메모리 단위

**비트(bit)**
- "**bi**nary digi**t**"(이진수 한 자리). 메모리는 물리적으로 스위치의 집합이고, 스위치 하나가 **0이냐 1이냐가 최소 단위**다. 비트 n개면 2^n가지 값을 표현.

**니블(nibble)**
- 비트 4개 = 바이트의 절반. 이름부터가 농담이다 — byte("한 입 베어물다")보다 작으니 nibble("살짝 베어물다")로 지었다.
- 값의 가짓수가 2^4=16가지라서, **니블 하나 = 16진수 한 자리**로 정확히 대응한다. 그래서 바이트 하나는 항상 16진수 두 자리로 쓴다(예: `1010 1111` = `AF`).

**바이트(byte)**
- 비트 8개 묶음. **메모리의 최소 저장 단위** — CPU가 메모리에 접근할 때 비트 하나씩이 아니라 **항상 바이트 단위**로 주소를 매긴다. 메모리를 "1바이트짜리 방이 일렬로 늘어선 복도"로 상상하면 된다.
- [04_Fundamental Data Types](../chapter04FundamentalDataTypes/main.md)에서 이걸 아파트 비유로 더 풀었다: RAM의 각 호수(주소)마다 정확히 1바이트짜리 방이 있고, `int`·`char` 같은 데이터 타입은 "이 방(들)에 든 비트열을 어떻게 해석할지"를 정하는 규칙이다.

 >*어원: IBM의 Werner Buchholz가 1956년에 만든 말로, 원래 "bite"(한 입)였는데 실수로 오타 나기 쉬운 "bit"와 혼동될까봐 일부러 y로 바꿔 "byte"로 적었다.*

**메모리 주소**
- 메모리들가 저장된 곳에 붙은 번지수. [포인터](../chapter12ReferencesAndPointers/main.md)가 저장하는 "가리키는 주소"가 바로 이 번지수다.
- 왜 16진수(hex)로 표기하나: 실제 주소는 이진수 숫자지만(예: 64비트 시스템이면 64자리 0/1), 그대로 쓰면 너무 길어 사람이 읽을 수 없다. 니블=16진수 한 자리라는 위 대응 덕분에, **64비트 주소를 16진수 16자리로 압축**해서 쓸 수 있다 — `0x00007ffee3a1b2c8` 같은 표기가 그 결과다. 이진수보다 4배 짧으면서 비트 패턴과의 변환은 여전히 기계적으로 쉽다.

**워드(word)**
- CPU가 한 번에 읽고 쓰고 연산하는 기본 단위. "32비트 시스템"·"64비트 시스템"이라 부를 때의 그 32/64비트가 바로 그 CPU의 워드 크기다.
- 포인터 크기가 가리키는 대상과 무관하게 시스템 아키텍처로 정해지는 이유([포인터 노트 7절](../chapter12ReferencesAndPointers/main.md))가 바로 이것 — 주소 하나를 담으려면 그 시스템의 워드 크기(32비트=4바이트, 64비트=8바이트)만큼의 공간이 필요하기 때문이다.

**단위 접두어(KB/MB/GB…)와 1024 문제**
- 컴퓨터 세계에선 "1킬로바이트 = 1000바이트"가 아니라 관행적으로 **1024(=2^10)바이트**로 써왔다. 2진수 기반 메모리 주소 공간이 항상 2의 거듭제곱 크기로 나뉘기 때문에(예: 4GB RAM = 2^32 주소), 10진수 접두어(킬로=1000)를 그대로 갖다 쓰되 값만 2^10에 슬쩍 맞춰 쓴 관행이다.
- 이 혼동을 없애려고 IEC가 **KiB(kibibyte)=1024B, MiB(mebibyte)=1024KiB** 같은 2진 전용 접두어를 표준화했지만, 실무에서는 여전히 OS·하드웨어 제조사마다 KB를 1000으로 쓰기도 1024로 쓰기도 해서 "내 500GB 디스크가 왜 465GB로 보이지?" 같은 혼란이 생긴다(제조사는 1GB=10^9바이트로 표기, OS는 1GB=2^30바이트로 계산하기 때문).

**메모리 계층 — 왜 "메모리"가 여러 층으로 나뉘나**
- 예: 책상 위(레지스터, 손 닿는 몇 권) → 옆 책장(캐시, 자주 쓰는 책) → 서재(RAM, 지금 읽는 중인 책 전부) → 창고(디스크, 안 읽는 책까지 전부)로 갈수록 용량은 커지지만 꺼내오는 데 걸리는 시간도 늘어난다.
- **레지스터**: CPU 내부에 몇 개뿐인 초고속 저장 공간. 지금 당장 연산 중인 값만 담는다.
- **캐시(L1/L2/L3)**: RAM보다 훨씬 빠르지만 훨씬 작은, CPU와 RAM 사이의 완충 지대. 최근/자주 쓴 데이터를 미리 당겨온다.
- **RAM(주기억장치)**: 흔히 그냥 "메모리"라 부르는 게 이거다 — 지금까지 이 노트에서 설명한 바이트·주소 체계가 실제로 사는 곳. 전원이 꺼지면 내용이 사라진다(휘발성).
- **디스크(SSD/HDD)**: 훨씬 느리지만 훨씬 크고, 전원이 꺼져도 유지된다(비휘발성).
- 이 계층이 존재하는 이유는 순전히 트레이드오프다 — 빠른 저장장치일수록 단가가 비싸서 용량을 늘릴 수 없다. 그래서 "자주 쓰는 소량은 빠르고 비싼 곳에, 어쩌다 쓰는 대량은 느리고 싼 곳에" 나눠 담는다.

**엔디안(endianness) — 여러 바이트를 저장하는 순서**
- `int`(4바이트) 하나처럼 여러 바이트로 이뤄진 값을 메모리에 놓을 때, 앞자리(큰 자릿수) 바이트를 먼저 놓을지 나중에 놓을지의 규약. **빅 엔디안**은 큰 자릿수부터(사람이 숫자 읽는 순서와 같음), **리틀 엔디안**은 작은 자릿수부터 저장한다. 대부분의 현대 x86/ARM 시스템은 리틀 엔디안이다.
- 이름의 유래: 조너선 스위프트의 『걸리버 여행기』에서 삶은 달걀을 뭉툭한 쪽(big end)부터 깨는지 뾰족한 쪽(little end)부터 깨는지로 전쟁까지 벌이는 나라 이야기(Big-Endian/Little-Endian) — 어느 쪽이 "옳다"랄 게 없는 관례 싸움이라는 걸 빗댄 이름이다.
- 왜 신경 써야 하나: 서로 다른 엔디안을 쓰는 두 시스템이 바이트 스트림을 그대로 주고받으면(네트워크 통신, 파일 포맷, ROS2 메시지 직렬화 등) 같은 바이트열이 다른 숫자로 읽힌다. 그래서 통신 규약은 보통 엔디안을 고정해서 명시한다(예: 네트워크 프로토콜은 관례적으로 빅 엔디안="네트워크 바이트 순서").

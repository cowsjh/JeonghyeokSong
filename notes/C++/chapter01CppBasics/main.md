## 1. 프로그램의 구조 — 문장과 함수

### 프로그램은 문장(statement)의 집합이다

컴퓨터에게 할 일을 지시하는 가장 작은 단위를 **문장(statement)** 이라 한다.  
문장 하나가 하나의 지시사항이고, 대부분 세미콜론(`;`)으로 끝난다.

```cpp
std::cout << "Hello";  // 문장 1 — 출력해라
int x { 5 };           // 문장 2 — 변수를 만들어라
x = x + 1;            // 문장 3 — 값을 바꿔라
```

### 함수 — 문장을 묶는 단위

관련된 문장들을 하나로 묶어 이름을 붙인 것이 **함수(function)** 다.  
함수를 만드는 것을 **정의(definition)**, 실행시키는 것을 **호출(call)** 이라 한다.

```cpp
#include <iostream>

// 함수 정의
void greet()
{
    std::cout << "Hello!\n";
    std::cout << "Welcome to C++\n";
}

int main()
{
    greet();  // 함수 호출 — greet 안의 문장들이 실행됨
    greet();  // 다시 호출 가능 — 코드 재사용
    return 0;
}
```

### main() 함수 — 프로그램의 시작점

모든 C++ 프로그램에는 반드시 `main()` 함수가 있어야 한다.  
프로그램 실행 시 운영체제가 `main()`을 제일 먼저 호출하고, `main()`이 끝나면 프로그램도 종료된다.

`return 0;`은 운영체제에게 "프로그램이 정상 종료됐다"고 알리는 신호다.  
0이 아닌 값을 반환하면 오류가 있었음을 나타낸다.

### 구문 오류 (Syntax Error)

C++은 엄격한 문법 규칙을 가진다. 규칙을 어기면 컴파일러가 **컴파일 에러**를 낸다.  
세미콜론 누락, 괄호 미닫기 등이 대표적이다. 에러 메시지가 뜨면 해당 줄 근처를 먼저 확인하라.

## 2. 주석 (Comments)

### 주석이란?

컴파일러가 무시하는 텍스트다. 사람을 위한 메모다.  
코드가 복잡해질수록, 나중에 다시 읽을 때, 다른 사람이 읽을 때 주석이 빛을 발한다.

### 두 가지 형식

```cpp
// 단일행 주석 — 이 줄 끝까지 무시됨

/* 다중행 주석
   여러 줄에 걸쳐 쓸 수 있다
   하지만 중첩은 안 됨 */
```

### 무엇을 주석으로 써야 하는가

**나쁜 주석** — 코드가 이미 말하는 것을 반복

```cpp
// x에 5를 대입
x = 5;

// cost 계산
cost = quantity * price;
```

**좋은 주석** — 코드만으로는 알 수 없는 **이유(why)** 를 설명

```cpp
// 플레이어가 실명 물약을 마셨으므로 시력 초기화
sight = 0;

// 상품은 쌍으로만 판매되므로 수량에 2를 곱함
cost = quantity * 2 * price;
```

코드를 읽는 사람은 코드가 **무엇을 하는지**는 볼 수 있다.  
주석은 **왜 그렇게 했는지**, **이 로직이 왜 필요한지**를 설명해야 한다.

### 주석 사용 수준

| 위치 | 목적 | 내용 |
|------|------|------|
| 함수/파일 위 | What | 이 함수/파일이 무엇을 하는지 |
| 함수 내부 | How | 어떤 방식으로 목표를 달성하는지 |
| 개별 문장 옆 | Why | 왜 이 결정을 내렸는지 |

## 3. 객체와 변수

### 메모리와 객체

프로그램이 실행되면 데이터를 저장할 공간이 필요하다. 이 공간이 **메모리**다.  
메모리의 특정 공간에 이름을 붙인 것이 **객체(object)**, 그중 명시적으로 이름이 있는 것이 **변수(variable)** 다.

메모리 주소를 직접 다루는 대신 변수 이름을 쓰면, 컴파일러가 알아서 주소를 관리해준다.

### 변수 정의

변수를 만드는 것을 **정의(definition)** 라 한다. 타입과 이름을 함께 지정한다.

```cpp
int x;          // int 타입 변수 x 정의
double width;   // double 타입 변수 width 정의
int a, b;       // 같은 타입 여러 개를 한 줄에 — 가능하지만 비권장
```

**타입(type)** 은 변수가 어떤 종류의 값을 저장할지, 메모리를 얼마나 차지할지를 결정한다.

## 4. 변수 초기화와 대입

### 초기화 vs 대입

두 개념은 비슷해 보이지만 다르다.

- **초기화(initialization)**: 변수를 만들면서 동시에 값을 설정
- **대입(assignment)**: 이미 만들어진 변수에 나중에 값을 넣음

```cpp
int x { 5 };  // 초기화 — 만들자마자 5로 설정
x = 10;       // 대입 — 나중에 10으로 변경
```

### 초기화 방법 3가지

```cpp
int a = 5;    // copy initialization — C에서 온 구식, 현대 C++에서는 비권장
int b ( 5 );  // direct initialization — 함수 호출처럼 생긴 방식
int c { 5 };  // brace initialization — 현대 C++ 권장 방식
```

**brace initialization(`{}`)을 권장하는 이유:**  
`int x { 3.9 }`처럼 소수를 정수 변수에 넣으려 하면 컴파일 에러를 낸다.  
`int x = 3.9`나 `int x(3.9)`는 경고만 내고 통과시켜 버린다.  
`{}`는 실수를 컴파일 시점에 잡아준다.

### 값 없이 초기화 — value initialization

`{}`만 쓰면 0(또는 타입의 기본값)으로 초기화된다.

```cpp
int x {};     // 0으로 초기화
double d {};  // 0.0으로 초기화
```

## 5. 초기화하지 않은 변수 — 쓰레기값

### 무슨 일이 일어나는가?

변수를 초기화하지 않으면 그 메모리 공간에 이전에 뭔가 남아 있던 값이 그대로 남는다.  
이것이 **쓰레기값(garbage value)** 이다. 예측 불가능하고, 실행할 때마다 달라질 수 있다.

```cpp
int x;                       // 초기화 안 함
std::cout << x << '\n';     // 0이 나올 수도, 32767이 나올 수도, -1094795586이 나올 수도
```

### 왜 위험한가?

- 매번 다른 결과가 나온다 — 재현이 안 되는 버그
- 어떤 때는 우연히 0이 나와서 정상처럼 보인다 — 숨어있는 버그
- C++ 표준은 이를 **정의되지 않은 동작(Undefined Behavior)** 이라 부른다

```cpp
// 로봇 관절 각도를 초기화하지 않으면?
double jointAngle;
setJointPosition(jointAngle);  // 어떤 값이 들어갈지 모름 — 하드웨어 손상 위험
```

> **규칙**: 변수를 정의할 때 항상 초기화해라. 값을 모르겠으면 `{}`로 0 초기화.

## 6. iostream — 입출력

### 왜 #include \<iostream\>이 필요한가?

C++ 자체는 화면 출력 기능을 언어 안에 내장하지 않는다.  
`iostream`은 입출력 기능을 모아둔 표준 라이브러리다.  
`#include`는 "이 파일의 내용을 여기에 복사해줘"라는 지시다.

### 출력 — std::cout

`cout`은 **c**haracter **out**put의 약자. `<<` 연산자로 값을 전달한다.

```cpp
#include <iostream>

int main()
{
    std::cout << "Hello\n";          // 문자열 출력
    std::cout << 42 << '\n';        // 정수 출력
    std::cout << "x = " << 5 << '\n'; // 연결 출력
    return 0;
}
```

### endl vs \n — 왜 \n이 더 좋은가?

```cpp
std::cout << "Hello" << std::endl; // 개행 + 버퍼 플러시
std::cout << "Hello" << '\n';      // 개행만
```

`std::endl`은 두 가지를 한다: 줄바꿈 **그리고** 출력 버퍼를 강제로 비운다(flush).  
버퍼를 비우는 작업은 느리다. 반복 출력 시 불필요하게 성능을 낮춘다.

`'\n'`은 줄바꿈만 한다. 버퍼는 알아서 효율적인 시점에 비워진다.

> **규칙**: 특별한 이유 없으면 `std::endl` 대신 `'\n'`을 써라.

### 입력 — std::cin

`cin`은 **c**haracter **in**put의 약자. `>>` 연산자로 변수에 값을 받는다.

```cpp
#include <iostream>

int main()
{
    std::cout << "정수를 입력하세요: ";
    int x{};
    std::cin >> x;                        // 키보드 입력을 x에 저장
    std::cout << "입력한 값: " << x << '\n';
    return 0;
}
```

여러 값을 한 번에 받을 수도 있다:

```cpp
int a{}, b{};
std::cin >> a >> b;  // 공백으로 구분된 두 값 입력
```

## 7. 키워드와 식별자 이름 짓기

### 키워드 (Keywords)

C++이 특별한 용도로 예약한 단어들이다. 변수/함수 이름으로 쓸 수 없다.  
`int`, `return`, `if`, `else`, `const`, `void`, `bool`, `class` 등 C++23 기준 92개.

### 식별자 규칙 (4가지)

1. 문자(대소문자), 숫자, 언더스코어(`_`)만 사용 가능
2. 숫자로 시작 불가 — `1value` X, `value1` O
3. 키워드 사용 불가 — `int` X
4. 대소문자 구분 — `value`와 `Value`는 다른 이름

### 좋은 이름 짓기

이름을 잘 짓는 것이 주석보다 훨씬 강력하다. 코드 자체가 설명이 된다.

| 나쁜 이름 | 좋은 이름 | 이유 |
|----------|----------|------|
| `x` | `jointAngle` | 무엇을 저장하는지 명확 |
| `t` | `elapsedSeconds` | 단위까지 포함 |
| `data` | `sensorReadings` | 구체적인 의미 |
| `ccount` | `customerCount` | 약어 지양 |
| `temp` | `temperature` | 축약 금지 |

- 변수명은 **소문자로 시작** (`myVariable`, `my_variable`)
- 함수명도 소문자로 시작 (`calculateAngle`)
- 밑줄로 시작하는 이름(`_count`)은 컴파일러/OS 예약어와 충돌 가능 — 피할 것
- 짧고 명확하게 — 단, 의미를 희생하면서 짧게 만들지 말 것

## 8. 공백과 코드 포맷팅

### C++는 공백을 자유롭게 쓸 수 있다

C++은 **공백 독립적(whitespace-independent)** 언어다.  
줄바꿈, 들여쓰기, 공백이 얼마나 있든 컴파일 결과는 같다.

```cpp
// 이것도
int main() { std::cout << "Hello"; return 0; }

// 이것도 동일하게 동작
int main()
{
    std::cout << "Hello";
    return 0;
}
```

하지만 코드는 **컴파일러가 읽는 게 아니라 사람이 읽는다.**  
포맷팅은 기능이 아니라 **가독성**을 위한 것이다.

### 권장 포맷팅 규칙

| 항목 | 권장 방식 |
|------|----------|
| 들여쓰기 | 스페이스 4칸 (또는 탭 1개) |
| 중괄호 `{}` | 함수/조건문과 같은 줄 X, **다음 줄에 단독으로** |
| 한 줄 길이 | 80자 이하 (넘으면 다음 줄로) |
| 연산자 줄바꿈 | 연산자를 다음 줄 앞에 배치 |

```cpp
// 중괄호는 별도 줄에
int main()
{
    // 들여쓰기 4칸
    std::cout << "Hello\n";
    return 0;
}

// 긴 줄은 연산자 앞에서 줄바꿈
std::cout << "value1: " << value1
          << "value2: " << value2
          << '\n';
```

### 일관성이 가장 중요하다

어떤 스타일을 쓰든 **프로젝트 전체에서 일관되게** 유지하는 것이 핵심이다.  
VS Code 같은 IDE의 자동 포맷팅 기능을 적극 활용하라.

> ROS2 프로젝트는 보통 `ament_clang_format` 또는 `clang-format`으로  
> 팀 전체의 코드 스타일을 자동으로 통일한다.

## 9. 리터럴과 연산자, 표현식

### 리터럴 (Literal)

소스코드에 직접 쓰인 고정된 값이다.

```cpp
42        // 정수 리터럴
3.14      // 부동소수점 리터럴
'A'       // 문자 리터럴
"Hello"   // 문자열 리터럴
true      // bool 리터럴
```

### 연산자 (Operator)

연산자는 피연산자(operand)를 받아 결과를 만든다.

| 종류 | 피연산자 수 | 예시 |
|------|-----------|------|
| 단항(unary) | 1개 | `-x`, `!b` |
| 이항(binary) | 2개 | `x + y`, `a * b` |
| 삼항(ternary) | 3개 | `조건 ? a : b` |

### 표현식 (Expression)

값 하나로 평가(evaluate)되는 조합이다. 리터럴, 변수, 연산자, 함수 호출을 조합할 수 있다.

```cpp
5           // 표현식 — 5로 평가
x + 3       // 표현식 — x의 값 + 3으로 평가
add(1, 2)   // 표현식 — 함수 반환값으로 평가
x > 0       // 표현식 — true 또는 false로 평가
```

표현식에 `;`을 붙이면 문장(statement)이 된다.

```cpp
x + 3;      // 표현식 문장 — 계산하지만 결과를 아무데도 안 씀 (의미 없음)
int y { x + 3 }; // 표현식의 결과를 변수에 저장 (유용)
```

## 핵심 요약 카드

| 개념 | 핵심 내용 |
|------|----------|
| 문장(statement) | 프로그램의 최소 실행 단위, 세미콜론으로 끝남 |
| main() | 모든 C++ 프로그램의 시작점, 반드시 존재해야 함 |
| 주석 | "무엇"이 아닌 "왜"를 써라 |
| 초기화 | `{}` 권장 — narrowing conversion 컴파일 에러로 조기 차단 |
| 쓰레기값 | 초기화 안 하면 예측 불가 값 → 항상 초기화 |
| `std::endl` vs `\n` | `endl`은 버퍼 flush로 느림 → `\n` 사용 |
| 식별자 규칙 | 문자/숫자/언더스코어, 숫자 시작 금지, 키워드 금지 |
| 이름 짓기 | 의미 + 단위 포함, 약어/축약 지양 |
| 포맷팅 | 컴파일러는 공백 무시 — 사람을 위해 일관되게 써라 |
| 표현식 | 값 하나로 평가되는 조합 — `;` 붙이면 문장 |

### 자주 하는 실수 TOP 5

1. 변수 초기화 안 함 → 쓰레기값으로 예측 불가 동작. **항상 `{}`로 초기화**
2. `std::endl` 남발 → 버퍼 flush로 느려짐. **`'\n'`으로 바꿔라**
3. 의미 없는 이름 (`x`, `temp`, `data`) → 나중에 본인도 모름. **이름에 의미 담아라**
4. 주석에 "무엇"을 씀 → 코드와 중복. **"왜"를 써라**
5. `;` 빠뜨림 → 컴파일 에러. 에러 메시지가 가리키는 줄 **한 줄 위를 확인**

다음 장인 [02_Functions and Files (함수와 파일)](../chapter02FunctionsAndFiles/main.md)에서는 함수를 여러 파일로 나누고 컴파일·링크하는 법을 다룬다.

## 6.1 — 연산자 우선순위와 결합성

### 왜 우선순위가 필요한가?

수식 `4 + 2 * 3`을 보자. 사람은 곱셈을 먼저 하는 게 자연스럽다고 알고 있지만, 컴퓨터는 그 규칙을 어디서 얻는가? 바로 **연산자 우선순위(precedence)** 표에서 얻는다. C++ 컴파일러는 이 표를 보고 어떤 연산자가 피연산자를 먼저 "묶는지" 결정한다.

**결합성(associativity)** 은 우선순위가 같은 연산자들이 여러 개 이어질 때 어느 방향부터 처리할지를 결정한다.

### 주요 우선순위 테이블

| 우선순위 (낮을수록 강함) | 연산자 | 결합성 |
|---|---|---|
| 2 | `()` `[]` `.` `->` | 좌→우 |
| 3 | `++` `--` `!` `~` `+` `-` (단항) | 우→좌 |
| 5 | `*` `/` `%` | 좌→우 |
| 6 | `+` `-` | 좌→우 |
| 14 | `&&` | 좌→우 |
| 15 | `\|\|` | 좌→우 |
| 16 | `=` `+=` `-=` `*=` `/=` | **우→좌** |

> 숫자가 낮을수록 먼저 처리된다 (1이 가장 강함).

### 예제로 확인

```cpp
4 + 2 * 3      // → 4 + (2 * 3) = 10   (곱셈이 덧셈보다 강함)
7 - 4 - 1      // → (7 - 4) - 1 = 2    (뺄셈은 좌→우 결합)
x = y = z      // → x = (y = z)         (할당은 우→좌 결합)
```

### 중요: 우선순위 ≠ 평가 순서

우선순위는 **어떤 피연산자가 어느 연산자에 묶이는가**만 결정한다. **묶인 피연산자들이 언제 계산되는가**는 별개 문제다.

```cpp
// 위험한 예: 함수 호출 순서가 컴파일러마다 다를 수 있음
printCalculation(getValue(), getValue(), getValue());

// 안전한 방법
int a{ getValue() };
int b{ getValue() };
int c{ getValue() };
printCalculation(a, b, c);
```

### 모범 사례

- 덧셈, 뺄셈, 곱셈, 나눗셈끼리만 섞이면 괄호 없어도 됨
- `&&`, `||`, 비교 연산자가 섞이면 **항상 괄호** 사용

```cpp
x = y + z + w;          // OK — 직관적
x = (y || z) && w;      // 괄호 필수
```

### 함정: `<<`와 약한 연산자 섞기

`<<`는 우선순위 7로 꽤 강하다. 출력문에 `<<`보다 약한 연산자(`=`, `+=`, `?:` 등)를 섞으면 `<<`가 먼저 피연산자를 묶어버린다.

```cpp
// ❌ 컴파일 에러
std::cout << x += 1 << '\n';
// 실제 해석: (std::cout << x) += (1 << '\n')
// - 오른쪽: 1 << '\n' 은 비트 시프트 → 1 << 10 = 1024 (문법상 합법)
// - 왼쪽: ostream에 += int 연산자가 없음 → "no match for operator+=" 에러

// ✅ 괄호로 묶으면 동작
std::cout << (x += 1) << '\n';

// ✅ 더 좋은 방법: 부작용과 출력을 분리 (6.4절 규칙)
x += 1;
std::cout << x << '\n';
```

> 6.6절의 `std::cout << (x < 0) ? "음수" : "양수"` 함정과 같은 패턴이다. **`<<`보다 약한 연산자를 출력문에 섞으면 항상 `<<`가 먼저 묶는다.**

## 6.2 — 산술 연산자

### 기본 연산자

| 연산자 | 의미 | 예 |
|---|---|---|
| `+x` | 단항 양수 (값 그대로) | `+5 → 5` |
| `-x` | 단항 음수 (부호 반전) | `-5 → -5` |
| `x + y` | 덧셈 | |
| `x - y` | 뺄셈 | |
| `x * y` | 곱셈 | |
| `x / y` | 나눗셈 | 정수/실수 구분 필요 |
| `x % y` | 나머지 | 정수만 가능 |

### 정수 나눗셈의 함정

두 피연산자가 모두 정수이면 결과도 정수다. **소수점 이하는 버려진다** (반올림 아님).

```cpp
7 / 4   // → 1  (1.75가 아님)
-7 / 4  // → -1 (0 방향으로 버려짐)
```

> **왜 이렇게 동작하나?** C++ 정수 타입은 소수점을 저장할 수 없다. 컴파일러가 결과를 억지로 정수에 넣으면서 소수 부분이 사라진다. 반올림이 아니라 "잘라내기(truncation)"다.

### 부동소수점 나눗셈

피연산자 중 하나라도 `double`이면 실수 나눗셈이 된다.

```cpp
7.0 / 4    // → 1.75
7 / 4.0    // → 1.75
static_cast<double>(7) / 4  // 정수를 실수로 명시 변환
```

### 0으로 나누기

```cpp
int x{ 5 / 0 };      // 정의되지 않은 동작 — 프로그램 충돌 가능
double y{ 5.0 / 0 }; // IEEE 754 환경에서 Inf 반환
```

항상 나누기 전에 분모가 0인지 확인하는 습관을 들이자.

### 산술 대입 연산자

```cpp
x += 4;  // x = x + 4
x -= 4;  // x = x - 4
x *= 4;  // x = x * 4
x /= 4;  // x = x / 4
x %= 4;  // x = x % 4
```

> **ROS2 연결**: 로봇 제어에서 조인트 각도에 오프셋을 더하거나 속도를 스케일링할 때 `+=`, `*=` 를 자주 쓴다.

## 6.3 — 나머지와 지수

### 나머지 연산자 `%`

정수 나눗셈 후 남은 나머지를 반환한다.

```cpp
7 % 4   // → 3  (7 = 4*1 + 3)
0 % 4   // → 0
```

**주요 용도**: 어떤 수가 다른 수로 나누어 떨어지는지 확인

```cpp
if (x % 2 == 0)   // x가 짝수이면
```

### 음수 나머지의 함정

결과 부호는 **왼쪽 피연산자를 따른다**.

```cpp
-6 % 4   // → -2  (수학에서는 2지만 C++은 -2)
 6 % -4  // →  2
```

> **함정**: `-5 % 2`는 -1이다. 홀수를 `x % 2 == 1`로 판별하면 음수에서 틀린다.

```cpp
// ❌ 음수에서 실패
bool isOdd(int x) { return (x % 2) == 1; }

// ✅ 올바른 방법
bool isOdd(int x) { return (x % 2) != 0; }
```

### 지수 연산

C++에는 지수 연산자가 없다. `^`는 XOR(비트 연산)이다.

```cpp
// 실수 지수: std::pow() 사용
#include <cmath>
double result{ std::pow(2.0, 10.0) };  // 2^10 = 1024.0
```

> **주의**: `std::pow()`는 내부적으로 부동소수점을 사용하므로 정수 거듭제곱에서 오차가 생길 수 있다. 정밀한 정수 거듭제곱이 필요하면 직접 반복 곱셈을 구현하는 것이 낫다.

## 6.4 — 증감 연산자와 부작용

### 전위(prefix) vs 후위(postfix)

| 형태 | 동작 | 반환값 |
|---|---|---|
| `++x` (전위) | x를 1 증가, 그 후 반환 | 증가된 값 |
| `x++` (후위) | 원본 복사 후 x를 1 증가, 복사본 반환 | 증가 전 값 |

```cpp
int x{ 5 };

int a{ ++x };   // x→6, a=6  (전위: 먼저 올리고 반환)
int b{ x++ };   // b=6, x→7  (후위: 복사 후 올림)
```

### 오해 주의: 후위는 "나중에" 올리는 게 아니다

후위 `x++`도 증가는 **평가되는 그 자리에서 즉시** 일어난다. 문장이 끝날 때 올리는 게 아니라, **올리긴 했는데 반환된 것이 옛 값의 복사본**일 뿐이다.

```cpp
int x{ 2 };
int a{ x++ };   // 1) 2를 복사 → 2) x는 즉시 3 → 3) 복사본 2를 반환
std::cout << a << ' ' << x << '\n';   // 출력: 2 3
```

> 후위 `x++` = "즉시 올리되, 옛 값을 돌려준다". "문장 끝나고 +1"로 이해하면 `x++ + x` 같은 코드에서 예측이 틀린다.

컴파일러가 `x++`와 `++x`를 처리하는 방식을 함수로 표현하면:

```cpp
// 후위 x++ 의 동작
int postfixIncrement(int& x)
{
    int temp{ x };   // ① x의 현재 값을 별도 임시 변수에 복사
    x = x + 1;       // ② 원본 x를 증가 (이 시점에 x는 이미 새 값)
    return temp;     // ③ 복사본(옛 값)을 반환 — x가 아니라!
}

// 전위 ++x 의 동작 — 복사본 없음
int& prefixIncrement(int& x)
{
    x = x + 1;
    return x;        // x 본인을 그대로 반환
}
```

후위의 `temp`가 바로 "임시 복사본"이고, 이 복사 비용이 전위를 권장하는 이유다.

### 왜 전위가 더 효율적인가?

후위 연산자는 **임시 복사본을 만든 뒤** 원본을 증가시키고 복사본을 반환한다. 복잡한 타입(예: 반복자)에서는 이 복사 비용이 크다. 단순 변수에서는 컴파일러가 최적화하지만, **습관적으로 전위를 쓰는 게 낫다**.

```cpp
++i;   // 권장
i++;   // 반환값을 쓰지 않는다면 굳이 후위일 필요 없음
```

### Side Effect (부작용)

**부작용**: 함수나 표현식이 반환값 이외에 관찰 가능한 상태 변화를 일으키는 것.  
예: 변수 값 변경, 화면 출력, 파일 쓰기.

`++x`는 반환값(x+1)을 낼 뿐만 아니라 x 자체를 바꾼다 — 이것이 부작용이다.

### 같은 문장에서 부작용 있는 변수를 두 번 쓰면 위험

```cpp
int x{ 5 };
int value{ add(x, ++x) };  // ❌ 미정의 동작
// 컴파일러마다 add(5, 6) 또는 add(6, 6) 결과가 달라짐
```

> **규칙**: 한 문장 안에서 값이 바뀌는(부작용이 있는) 변수는 한 번만 사용하라.

## 6.5 — 쉼표 연산자

### 개념

쉼표 연산자(`,`)는 **여러 표현식을 순서대로 평가**하고, **마지막 표현식의 값**을 반환한다.

```cpp
int x{ 1 };
int y{ 2 };
std::cout << (++x, ++y) << '\n';  // x→2, y→3, 출력: 3
```

### 우선순위 함정

쉼표 연산자는 **모든 연산자 중 가장 낮은 우선순위**를 가진다.

```cpp
z = a, b;    // → (z = a), b  → z에 a가 대입되고, b는 그냥 버려짐
z = (a, b);  // → z = b  (의도한 경우라면 이렇게 작성)
```

### 사용 지침

> **`for` 루프 내부를 제외하고는 쉼표 연산자를 쓰지 마라.**

함수 호출의 인자를 구분하는 쉼표(`foo(a, b)`)는 쉼표 연산자가 아니다 — 혼동하지 말 것.

### for 루프에서의 사용법 (유일하게 허용되는 곳)

루프 변수 두 개를 동시에 갱신할 때 쓴다:

```cpp
for (int i{ 0 }, j{ 9 }; i < j; ++i, --j)   // 양쪽에서 좁혀오기
    std::cout << i << ' ' << j << '\n';
// 출력: 0 9 / 1 8 / 2 7 / 3 6 / 4 5
```

- for의 증감부는 **표현식 하나**만 받는 자리라서, `++i`와 `--j`를 둘 다 하려면 쉼표 연산자로 묶는 수밖에 없다. (일반 코드에서는 그냥 두 문장 `a; b;`로 쓰면 되므로 필요 없음)
- **주의**: 첫 번째 칸의 `int i{ 0 }, j{ 9 }`의 쉼표는 변수 선언 구분자이지 쉼표 연산자가 아니다. 같은 for 문 안에 정체가 다른 쉼표 두 개가 있는 셈.

## 6.6 — 조건 연산자

### 개념

조건 연산자(`?:`)는 C++의 유일한 **삼항 연산자**다.

```
조건 ? 참일 때 값 : 거짓일 때 값
```

if-else를 표현식 안에 내장할 수 있다.

```cpp
int max{ (x > y) ? x : y };       // x, y 중 큰 값
```

### 상수 초기화에서 유용

```cpp
constexpr bool bigClass{ false };
constexpr int size{ bigClass ? 30 : 20 };  // if-else로는 constexpr 불가
```

### 우선순위 함정

```cpp
// ❌ 잘못된 예
std::cout << (x < 0) ? "음수" : "양수";
// 실제 평가: (std::cout << (x < 0)) ? "음수" : "양수"
// cout에 bool 값이 출력되고, "양수"/"음수"는 버려짐

// ✅ 올바른 예
std::cout << ((x < 0) ? "음수" : "양수");
```

복합 표현식 안에서 쓸 때는 **전체를 괄호로 감싸라**.

### 타입 일치 규칙

두 번째와 세 번째 피연산자의 타입이 호환되어야 한다.

```cpp
(false ? 1 : 2.2)    // OK: int → double 자동 변환
(true ? -1 : 2u)     // 주의: 음수를 unsigned로 변환 → 매우 큰 수
```

### 사용 가이드

**적합한 경우**: 간단한 값 선택, 변수 초기화, 함수 반환값  
**피해야 할 경우**: 조건이 복잡하거나 중첩될 때 → if-else 사용

## 6.7 — 관계 연산자와 부동소수점 비교

### 관계 연산자 6가지

| 연산자 | 의미 | 예 |
|---|---|---|
| `==` | 같다 | `x == y` |
| `!=` | 다르다 | `x != y` |
| `<` | 미만 | `x < y` |
| `>` | 초과 | `x > y` |
| `<=` | 이하 | `x <= y` |
| `>=` | 이상 | `x >= y` |

### bool 변수 비교 모범 사례

```cpp
// ❌ 불필요하게 명시적
if (isValid == true) ...
if (isValid == false) ...

// ✅ 권장
if (isValid) ...
if (!isValid) ...
```

### 부동소수점 비교의 함정

컴퓨터는 `0.1`을 정확히 표현하지 못한다. 계산 과정에서 아주 작은 오차가 쌓인다. (원리는 [Chapter 4 — 8. 부동소수점](../chapter04FundamentalDataTypes/main.md) 참고)

```cpp
double d1{ 100.0 - 99.99 };   // 수학적으로 0.01
double d2{ 10.0 - 9.99 };     // 수학적으로 0.01

if (d1 == d2) ...  // false 반환 가능
// 실제로 d1 ≈ 0.010000000000005116
//        d2 ≈ 0.009999999999997868
```

> **규칙**: 계산으로 얻은 부동소수점 값에 `==`나 `!=`를 쓰지 마라.

**안전한 예외**: 리터럴로 직접 초기화한 상수끼리 비교

```cpp
constexpr double gravity{ 9.8 };
if (gravity == 9.8) ...   // OK: 계산 없이 리터럴 비교
```

### 근사 비교 함수 (권장 패턴)

#### 방법 1: 절댓값 차이

```cpp
bool approxEqual(double a, double b, double epsilon)
{
    return std::abs(a - b) <= epsilon;
}
```

문제: `epsilon`을 입력 크기에 맞게 직접 조정해야 한다.

#### 방법 2: 상대 오차 (Knuth 알고리즘)

```cpp
bool approxEqualRel(double a, double b, double relEpsilon)
{
    return std::abs(a - b) <= std::max(std::abs(a), std::abs(b)) * relEpsilon;
}
// relEpsilon = 1e-8 → 1억분의 1 비율 오차 허용
```

#### 방법 3: 하이브리드 (권장)

```cpp
bool approxEqual(double a, double b, double absEps, double relEps)
{
    if (std::abs(a - b) <= absEps)   // 두 값이 0 근처일 때
        return true;
    return std::abs(a - b) <= std::max(std::abs(a), std::abs(b)) * relEps;
}
// 사용: approxEqual(a, b, 1e-12, 1e-8)
```

> **ROS2 연결**: 로봇 관절 목표 도달 판별(`if (currentAngle == targetAngle)`)에 절대로 `==`를 쓰면 안 된다. 항상 오차 범위 비교를 사용한다.

## 6.8 — 논리 연산자

### 3가지 논리 연산자

| 연산자 | 기호 | 의미 |
|---|---|---|
| 논리 NOT | `!` | 참↔거짓 반전 |
| 논리 AND | `&&` | 둘 다 참이면 참 |
| 논리 OR | `\|\|` | 하나라도 참이면 참 |

### 논리 NOT `!`

```cpp
bool tooLarge{ x > 100 };
if (!tooLarge) { /* 처리 */ }
```

**우선순위 함정**: `!`는 `>`보다 우선순위가 높다.

```cpp
if (!x > y)       // ❌ → (!x) > y → 0 > y (의도와 다름)
if (!(x > y))     // ✅ 명시적 괄호 필수
```

### 논리 OR `||`

```cpp
if (value == 0 || value == 1)   // OK

if (value == 0 || 1)            // ❌ 항상 참 (1이 true로 변환됨)
```

### 논리 AND `&&`

```cpp
if (value > 10 && value < 20)   // 범위 검사
```

### Short-Circuit Evaluation (단락 평가)

AND와 OR은 결과가 이미 확정되면 나머지 피연산자를 **평가하지 않는다**.

```cpp
// AND: 왼쪽이 false면 오른쪽은 건너뜀
if (x == 1 && ++y == 2)    // x가 1이 아니면 ++y 실행 안 됨

// OR: 왼쪽이 true면 오른쪽은 건너뜀
if (x == 1 || ++y == 2)    // x가 1이면 ++y 실행 안 됨
```

> **왜 이렇게 동작하나?** AND는 하나라도 false면 결과가 false, OR은 하나라도 true면 결과가 true다. 더 볼 필요가 없으니 컴파일러가 나머지를 건너뛴다. 성능 최적화이기도 하다.

**주의**: 조건식 안에 부작용(증감, 함수 호출)이 있으면 short-circuit 때문에 그 부작용이 실행되지 않을 수 있다.

### AND와 OR 혼합

AND(`&&`)가 OR(`||`)보다 우선순위가 높다.

```cpp
a || b && c    // → a || (b && c)  (AND 먼저)
```

혼합할 때는 항상 괄호로 의도를 명시하라.

```cpp
(a && b) || (c && d)   // 명확함
```

### De Morgan의 법칙

NOT을 괄호 안으로 분배할 때 AND↔OR이 뒤바뀐다.

```cpp
!(x && y)   ≡   !x || !y
!(x || y)   ≡   !x && !y
```

```cpp
// 복잡한 조건을 읽기 쉽게 변환
if (!(isReady && isConnected))    // 읽기 어려움
if (!isReady || !isConnected)     // 더 직관적
```

### XOR 구현

C++은 논리 XOR 연산자가 없다. bool 타입에서는 `!=`로 대체한다.

```cpp
if (a != b)   // a XOR b (bool 타입)
```

## 핵심 요약 카드

| 개념 | 핵심 내용 |
|---|---|
| 우선순위 | 숫자 낮을수록 강함; `*/%` > `+-` > `<>` > `==!=` > `&&` > `\|\|` > `=` |
| 결합성 | 대부분 좌→우; 할당/단항/조건 연산자는 우→좌 |
| 정수 나눗셈 | 소수 버림(truncation), 반올림 아님 |
| 음수 나머지 | 결과 부호 = 왼쪽 피연산자 부호 |
| 지수 연산 | `^`는 XOR; 실수 지수는 `std::pow()` |
| 전위 vs 후위 | 전위가 효율적; 반환값 쓸 때만 후위 사용 |
| Short-Circuit | `&&`: 왼쪽 false면 오른쪽 스킵 / `\|\|`: 왼쪽 true면 오른쪽 스킵 |
| 부동소수점 `==` | 계산된 값끼리 절대 사용 금지; 근사 비교 함수 사용 |
| 조건 연산자 | 복합식에서 전체를 괄호로 감쌀 것 |
| De Morgan | `!(A && B)` = `!A \|\| !B` / `!(A \|\| B)` = `!A && !B` |

### 자주 하는 실수 TOP 6

1. **정수 나눗셈 망각**: `7 / 4`가 `1`인데 `1.75`로 착각
2. **음수 홀수 판별 오류**: `x % 2 == 1` 대신 `x % 2 != 0` 사용해야 함
3. **부동소수점 `==` 비교**: 계산된 double끼리 `==` 사용 → 항상 근사 비교 함수로
4. **`!` 우선순위 무시**: `!x > y`가 `!(x > y)`가 아님 → `!(x > y)`로 괄호 필수
5. **`||` 오른쪽에 리터럴**: `value == 0 || 1`은 항상 true — 비교 대상을 명시해야 함
6. **출력문에 약한 연산자 섞기**: `std::cout << x += 1`은 컴파일 에러 — `(x += 1)`처럼 괄호 필수
